# Telegram-бот «Календарь-напоминалка»

Бот позволяет создавать события с названием, описанием и датой, подписывать
на них других пользователей Telegram по username и автоматически присылает
напоминания за **48 часов** и за **24 часа** до события.

## Установка

```bash
cd telegram-reminder-bot
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

Токен бота уже записан в файле `.env` (`BOT_TOKEN`). Там же можно поменять
часовой пояс (`TIMEZONE`, по умолчанию `Europe/Moscow`) — именно в этом поясе
нужно будет вводить дату события.

## Запуск

```bash
python bot.py
```

Бот будет работать, пока запущен процесс (polling).

## Постоянная работа 24/7 на bothost.ru

Бот развёрнут на [bothost.ru](https://bothost.ru) (тариф **Basic**, 99₽/мес,
сервер в Нидерландах — поэтому Telegram API доступен без VPN) с постоянным
диском (Volume), чтобы события не терялись при перезапусках.

Настройка в панели bothost.ru:

1. Создайте бота в дашборде → способ деплоя: **Git** (GitHub/GitLab) или
   **ZIP-архив** — любой удобный.
2. **Точка входа**: `bot.py`
3. **Переменные окружения** (Environment variables) — задайте там, не храните
   секреты в репозитории/архиве:
   - `BOT_TOKEN` — токен бота
   - `TIMEZONE` — например `Europe/Moscow`
   - `DATA_DIR` — `/app/data` (путь постоянного Volume на тарифе Basic/Pro —
     именно туда `db.py` положит файл `events.db`, чтобы он не стирался при
     обновлениях контейнера)
4. Убедитесь, что к проекту подключён **Volume** (постоянное хранилище) —
   без него на свободном тарифе данные стираются при каждом перезапуске.
5. Задеплойте — платформа сама поставит зависимости из `requirements.txt` и
   запустит `bot.py`.

Файл `.env` в архиве — только для локального запуска/тестирования на своём
компьютере, он **не должен** попадать в git-репозиторий (уже в `.gitignore`).
Используйте `.env.example` как шаблон.

## Как пользоваться

1. **Каждый, кому должны приходить напоминания** (включая вас самих), должен
   хотя бы один раз написать боту `/start`. Без этого Telegram не позволяет
   боту написать пользователю первым — он просто не будет знать, куда слать
   сообщение.
2. `/add` — создать событие. Бот по шагам спросит:
   - название;
   - описание (или `-`, если без описания);
   - дату и время в формате `ДД.MM.ГГГГ ЧЧ:MM`, например `25.12.2026 18:30`;
   - username-ы получателей напоминаний через пробел/запятую, например
     `@ivan @maria` (или `-`, если напоминания нужны только вам).
3. `/list` — список ваших ближайших событий (созданных вами или тех, на
   которые вы подписаны).
4. `/delete` — показывает список ваших событий с кнопками, нажатие на кнопку
   удаляет событие (и отменяет его напоминания).
5. `/cancel` — отменить создание события на любом шаге.

## Как это работает технически

- Данные хранятся в SQLite-файле `events.db` (создаётся автоматически рядом
  с `bot.py`): таблицы `events`, `event_subscribers`, `users` (username →
  chat_id, заполняется при `/start`).
- Напоминания планируются через `JobQueue` (APScheduler) на точное время
  `дата события − 48ч` и `дата события − 24ч`.
- При перезапуске бота все будущие события перечитываются из базы и
  напоминания переставляются заново (флаги `reminder_48_sent` /
  `reminder_24_sent` не дают отправить напоминание повторно). Если бот был
  выключен и момент напоминания уже прошёл, напоминание отправится сразу
  после запуска.
- Если один из указанных username ещё не писал боту `/start`, бот создаст
  событие, но предупредит, что этому человеку напоминания пока не придут.
